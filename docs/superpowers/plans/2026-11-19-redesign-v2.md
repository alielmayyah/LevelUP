# LevelUP Redesign v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the rejected 18 November UI with a calm, data-first app. The new app has:
- one answer per screen, no glass or glow, almost no motion except the new-result moment;
- range-aware rules, so the app never contradicts itself;
- three tabs: Home · Scans · Settings.

The old screens are kept in the code, out of the navigation.

**Architecture:**
1. **Foundation first:** tokens, a `src/legacy/` boundary, number/date formatting, the motion system, the tab bar, app start.
2. **Then the rules:** one range-aware engine in the mock API, so every screen reads the same verdicts.
3. **Then the screens,** rebuilt on a small set of primitives and three signature graphics:
   - **the Line-up:** bullet bars against the normal band;
   - **the Record wall:** level stamps;
   - **the Print:** the new-result reveal.

**Tech Stack:** Ionic React 8, Vite, Capacitor, Tailwind v4, i18next, GSAP (reveal only), Vitest + Testing Library, Playwright + axe-core.

**Spec:** [`docs/redesign/AUDIT-2026-11-19.md`](../../redesign/AUDIT-2026-11-19.md) (findings referenced as D#, S#, V#, M#, C#). The product rules in [`docs/redesign/PLAN.md`](../../redesign/PLAN.md) still apply wherever this plan doesn't override them.

## Global Constraints

- **Languages:** Arabic is the default, Egyptian colloquial, never MSA. Every string exists in `ar` and `en`. Digits are 0–9 in both. RTL is correct (logical CSS only).
- **Themes:** dark is the default; light is supported. Colors come from tokens only; `npm run check-colors` passes.
- **Sizes:** 320 px to desktop, portrait and landscape; safe areas respected.
- **Text floor:** 12 px Latin, 13 px Arabic, inputs 16 px. Weights 400, 500, 600 and 700 only.
- **Numbers:** every standalone number goes through `Num`. Signs come from `formatSigned`, never typed into a translation string. Units are Readex, not Alexandria.
- **Copy limits:**
  - one headline per screen, ≤ 8 words (EN) / ≤ 10 (AR);
  - ≤ 25 words per module;
  - no subtitles that restate a title;
  - each number appears once per screen;
  - every change names its baseline ("since June" / "من يونيو").
- **Color meaning:**
  - green only for a real better change beyond the noise;
  - amber (with an icon and a word) for "watch";
  - neutral grey for steady;
  - never red on a body metric;
  - red only on a destructive dialog's confirm button.
- **One primary (filled) button per screen.**
- **Motion:**
  - daily screens never replay entrances; no bounce or overshoot except the reveal's emblem;
  - the only easing curves are those in Task 4's tokens;
  - reduced motion means opacity only (≤ 200 ms).
- **Old code is moved, not deleted** (O5). Nothing outside `src/legacy/` imports from it, except `src/legacy/routes.tsx`.
- **Owner's batching rule:**
  - write tests in every task, but don't run the suites between tasks;
  - each task ends with `npx tsc --noEmit` and a local commit;
  - Task 19 runs everything, fixes failures, then pushes `dev`;
  - commit with the repo owner's identity, no AI attribution;
  - stage only your own files (other sessions share this tree).
- **Bundle:** initial JS ≤ 200 KB gzip (it is 209 KB today).

## Review Focus

1. **A member whose fat is already below the healthy range.** No screen may call fat loss "better", offer a fat-loss level, goal or next-level target, or play the reveal for it. Covered by `journey.test.ts > below-range fat is never rewarded` (Task 7) and `Home.test.tsx > 101 sees no fat-loss praise` (Task 10).
2. **Mixed results** (muscle down, fat down). It isn't a celebration, earns no level, and the verdict says "watch". Covered by `journey.test.ts > a cut that loses muscle earns nothing` (Task 7).
3. **Arabic with signed numbers, ranges and Latin place names.** No sign may end up after the digits, no arrow may point backwards, and "InBody 770" must never be split. Covered by `format.test.ts > signs stay in front in Arabic` (Task 3) and `e2e/rtl.spec.ts` (Task 19).
4. **Two members on one phone, a deleted scan, an old notification.** The reveal fires only for a newer unseen scan of the signed-in member. Covered by `seenScan.test.ts` (Task 8).
5. **A slow network.** Switching Compare picks quickly must never show the older pair's result; loads under 300 ms show no skeleton. Covered by `useApi.test.tsx > a stale response never overwrites a newer one` (Task 8) and `Skeleton.test.tsx` (Task 4).
